CORE ENGINE
AI-Assisted Customs Examination Platform
Detailed Functional, UI/UX, Data & Demo Implementation Specification
This document is a complete hand-off specification for a junior developer. It defines what to build, how every new page connects to the current CORE Engine, the exact KPI/visual/table headings, data fields, interactions, demo logic, database additions, API structure, implementation order and acceptance criteria.
1. Executive Summary
The existing CORE Engine already handles container registration, transparent cargo risk scoring, readiness validation, resource availability and conflict-free examination scheduling. The expansion should preserve that operational core and add intelligence before scheduling and learning/governance after examination.
Target story: Container/CusDec Data → Document Intelligence → HS Code Intelligence → Fraud & Anomaly Detection → AI Risk Intelligence → Human Recommendation Review → Readiness → CORE Optimizer → Examination → Outcome → Audit & Analytics.
The Asia-Pacific report is regional rather than a Sri Lanka-specific specification. Therefore, this design applies its themes—risk/fraud detection, document processing, AI-ready data and human-supervised governance—to the existing CORE Engine as a proposed demo architecture.

3. Common Design Rules
Use one shared synthetic dataset across every page; never hard-code unrelated page values.
Use Container Number and CusDec Number as the main cross-page identifiers.
Risk/status colours must be consistent: Critical red, High orange, Medium yellow, Low green.
Every AI-style recommendation must show reasons/evidence and a human action.
Use wording such as Recommended Action, Possible Anomaly, Needs Review. Do not display unverified alerts as confirmed fraud.
Global filters where relevant: Date, Risk Level, Status, Importer, HS Code, Country of Origin, Inspection Type.
Clearly mark simulated/sample values. Do not present invented data as official Sri Lanka Customs statistics.

25. Final Instruction to the Junior Developer
Do not rebuild CORE Engine as a separate application. Extend the current workflow. Intelligence modules create evidence and recommendations; Readiness controls eligibility; the existing optimizer turns eligible priority into a resource-feasible schedule; officers record outcomes; governance and analytics expose the complete decision chain.
If a feature requires real Sri Lanka Customs data, a production OCR model, a production HS-classification model, or an official legal/business rule that has not been supplied, implement the workflow with clearly marked synthetic/demo data and configurable rules. Do not invent an official Customs rule.
